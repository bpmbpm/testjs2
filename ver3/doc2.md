# Детальное описание работы программы SVG Viewer

## 1. Общий жизненный цикл приложения

### 1.1 Загрузка и инициализация
При открытии страницы в браузере происходит следующая последовательность:

1. Браузер загружает `index.html` и применяет стили из `styles.css`.
2. Загружается `config.js` — он создаёт глобальную переменную `window.svgFileList` со списком URL SVG-файлов.
3. Загружается `app.js` — определяются все модули (`UTILS`, `STATE`, `DATA`, `RENDER`, `EVENTS`, `RESIZER`), но **логика ещё не выполняется**.
4. Срабатывает событие `DOMContentLoaded` (или выполняется сразу, если документ уже готов), вызывается функция `initApp()`.
5. `initApp()` выполняет:
   - Логирует запуск приложения.
   - Вызывает `STATE.initFromConfig()` — считывает `window.svgFileList` и сохраняет валидные URL в `STATE.appState.fileList`.
   - Вызывает `RENDER.renderFileList()`, `RENDER.renderProperties()`, `RENDER.renderDiagram()` — отрисовывает начальное состояние интерфейса (пустой список свойств, заглушка в diagram).
   - Навешивает обработчик клика на контейнер `#diagram-content`.
   - Инициализирует `RESIZER.init()` — настраивает перетаскивание верхней границы панели лога.

### 1.2 Основной цикл взаимодействия
После инициализации приложение переходит в режим ожидания событий. Любое действие пользователя (клик по файлу, клик по диаграмме, изменение размера панели) вызывает соответствующий обработчик из `EVENTS` или `RESIZER`, который:
1. Логирует событие через `UTILS.log`.
2. Обновляет состояние через `STATE`.
3. Запрашивает данные через `DATA` (если нужно).
4. Перерисовывает интерфейс через `RENDER`.

## 2. Описание основных функций по модулям

### 2.1 Модуль `UTILS` — вспомогательные функции

| Функция | Назначение | Параметры | Возвращает |
|---------|------------|-----------|------------|
| `log(groupName, funcName, message, params)` | Формирует и выводит строку лога в консоль и в DOM-панель `#log-content`. Формат: `[время] [группа] функция: сообщение [доп.параметры]`. | `groupName` — категория (STATE, DATA, EVENTS...), `funcName` — имя функции, `message` — текст, `params` — объект с доп. данными (url, error, count и т.п.) | Ничего (побочный эффект: запись в DOM) |
| `text(str)` | Безопасно приводит значение к строке и убирает пробелы по краям. Используется при чтении атрибутов SVG. | `str` — любое значение | Строку или пустую строку, если `str` не определено |
| `getFileNameFromUrl(url)` | Извлекает имя файла из URL (часть после последнего `/`). | `url` — строка URL | Имя файла (например, `"diagram1.svg"`) |

### 2.2 Модуль `STATE` — управление состоянием

| Функция | Назначение |
|---------|------------|
| `initFromConfig()` | Читает `window.svgFileList`, фильтрует пустые/некорректные значения, сохраняет результат в `STATE.appState.fileList`. |
| `isValid()` | Проверяет, выбран ли файл (`!!STATE.appState.selectedFile`). Возвращает `true`/`false`. |
| `setSelectedFile(fileUrl)` | Устанавливает выбранный файл, **сбрасывает** `svgDoc` и `shapes` в `null`/`[]` (чтобы старые данные не отображались до загрузки нового файла). |
| `clearSelection()` | Сбрасывает выбор файла (вызывает `setSelectedFile(null)`). |

**Структура состояния:**
```javascript
appState: {
    fileList: [],        // Массив URL из config.js
    selectedFile: null,  // URL текущего выбранного файла
    svgDoc: null,        // Распарсенный DOM-документ SVG
    shapes: []           // Массив объектов с атрибутами фигур
}
```

### 2.3 Модуль `DATA` — работа с данными

| Функция | Назначение |
|---------|------------|
| `loadSvg(url)` | Асинхронно загружает SVG по URL через `fetch`, парсит через `DOMParser` в `image/svg+xml`, проверяет наличие корневого `<svg>`. Возвращает `Document` или бросает ошибку. |
| `analyzeShapes(doc)` | Обходит все элементы SVG-документа, ищет теги `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `path`, `g`. Для каждого извлекает атрибуты (`id`, `class`, `cx`, `cy`, `r`, `x`, `y`, `width`, `height`, `d`) и формирует массив объектов. |

### 2.4 Модуль `RENDER` — отрисовка интерфейса

| Функция | Назначение |
|---------|------------|
| `renderFileList()` | Строит `<ul>` список файлов в `#filelist-content`. Подсвечивает выбранный файл классом `.selected`. |
| `renderProperties()` | Если файл не выбран — показывает заглушку. Если выбран, но фигур нет — показывает "не найдено". Иначе строит таблицу с колонками: Тип, ID, Класс, Координаты/Параметры. |
| `renderDiagram()` | Если файл не выбран — показывает подсказку. Если `svgDoc` уже загружен — клонирует `<svg>` и вставляет в `#diagram-content`. Если ещё грузится — показывает "Загрузка диаграммы...". |

## 3. Максимально детальное описание `const EVENTS`

Модуль `EVENTS` — это **контроллер** приложения. Он обрабатывает все действия пользователя и координирует работу остальных модулей. Содержит два публичных метода.

### 3.1 `EVENTS.handleFileListItemClick(url)`

**Назначение:** Обрабатывает клик пользователя по элементу списка файлов.

**Триггер:** Вызывается из `RENDER.renderFileList()` при навешивании обработчика на каждый `<li>` в списке файлов.

**Параметры:**
- `url` (string) — URL выбранного SVG-файла (берётся из `li.dataset.url`).

**Пошаговая логика работы:**

1. **Логирование входа:**
   ```
   [EVENTS] handleFileListItemClick: Клик по файлу в filelist [url: ...]
   ```

2. **Обновление состояния:**
   - Вызывает `STATE.setSelectedFile(url)`.
   - Это устанавливает `selectedFile = url` и **сбрасывает** `svgDoc = null`, `shapes = []`.
   - **Важно:** сброс нужен, чтобы пока новый файл грузится, в `properties` и `diagram` не отображались данные от предыдущего файла.

3. **Немедленная перерисовка интерфейса (синхронная):**
   - `RENDER.renderFileList()` — перерисовывает список, чтобы подсветить новый выбранный файл.
   - `RENDER.renderProperties()` — показывает заглушку "В SVG не найдено фигур" (т.к. `shapes` теперь пустой).
   - `RENDER.renderDiagram()` — показывает "Загрузка диаграммы..." (т.к. `svgDoc` теперь `null`).

4. **Асинхронная загрузка данных:**
   - Вызывает `DATA.loadSvg(url)` — возвращает Promise.
   - **При успехе (`.then`):**
     - Сохраняет распарсенный документ: `STATE.appState.svgDoc = doc`.
     - Вызывает `DATA.analyzeShapes(doc)` и сохраняет результат: `STATE.appState.shapes = ...`.
     - Снова вызывает `RENDER.renderProperties()` — теперь таблица отрисовывается с реальными данными.
     - Снова вызывает `RENDER.renderDiagram()` — теперь вставляется реальный клон `<svg>`.
   - **При ошибке (`.catch`):**
     - Логирует ошибку:
       ```
       [EVENTS] handleFileListItemClick: Ошибка при загрузке SVG после клика [error: ..., url: ...]
       ```
     - **Важно:** в UI ошибка не показывается (нет alert, нет красных надписей). Пользователь видит только сообщение в логе. Диаграмма остаётся в состоянии "Загрузка диаграммы...".

**Побочные эффекты:**
- Запись 2–3 строк в лог (в зависимости от успеха).
- Изменение глобального состояния `STATE.appState`.
- Многократная перерисовка DOM (до 5 вызовов `RENDER` за один клик).

### 3.2 `EVENTS.handleDiagramClick()`

**Назначение:** Обрабатывает клик пользователя по области панели `diagram`.

**Триггер:** Навешивается в `initApp()` на контейнер `#diagram-content` через `addEventListener('click', ...)`.

**Параметры:** нет (использует глобальное состояние `STATE`).

**Пошаговая логика работы:**

1. **Логирование входа:**
   ```
   [EVENTS] handleDiagramClick: Клик в область diagram
   ```

2. **Проверка условия — выбран ли файл:**
   - Вызывает `STATE.isValid()`.
   - **Если файл НЕ выбран** (`selectedFile === null`):
     - Логирует специфическое событие:
       ```
       [EVENTS] diagram.click.no-selection: Не выбран элемент filelist — действие невозможно
       ```
     - **Выходит из функции через `return`** — никаких дальнейших действий не выполняется.
     - Это защита от выполнения действий в некорректном состоянии.
   - **Если файл выбран:**
     - Переходит к шагу 3.

3. **Выполнение действия (заглушка):**
   - Логирует:
     ```
     [EVENTS] handleDiagramClick: Клик в diagram при выбранном файле (заглушка действия)
     ```
   - На этом месте в будущем может быть добавлена реальная логика: зум, панорамирование, выделение фигур, экспорт и т.п.

**Побочные эффекты:**
- Запись 2 строк в лог (одна всегда, вторая — только при выбранном файле).
- Никаких изменений в `STATE` и никакой перерисовки.

### 3.3 Сводная таблица методов `EVENTS`

| Метод | Вход | Условия | Изменяет STATE | Вызывает RENDER | Логи |
|-------|------|---------|----------------|-----------------|------|
| `handleFileListItemClick(url)` | URL файла | Всегда выполняется | Да (сброс + установка) | Да (3–5 раз) | 2–3 |
| `handleDiagramClick()` | — | `isValid() === true` | Нет | Нет | 1–2 |

### 3.4 Ключевые особенности дизайна `EVENTS`

1. **Разделение синхронной и асинхронной работы.** Сначала интерфейс обновляется синхронно (чтобы пользователь сразу увидел отклик — "Загрузка диаграммы..."), затем асинхронно подгружаются данные и интерфейс обновляется повторно.

2. **Отказоустойчивость.** Ошибки загрузки SVG не ломают приложение — они только логируются. Пользователь может выбрать другой файл и попробовать снова.

3. **Защитные проверки.** В `handleDiagramClick` есть явная проверка `STATE.isValid()`, предотвращающая выполнение действий в некорректном состоянии. Это пример принципа "fail-fast".

4. **Именованные события в логе.** Событие `diagram.click.no-selection` имеет собственное уникальное имя, что позволяет легко фильтровать логи и находить конкретные ситуации при отладке.

5. **Отсутствие UI-ошибок.** Ни один метод `EVENTS` не показывает `alert()` и не рисует красные сообщения поверх интерфейса. Все ошибки — только в логе. Это делает интерфейс чище и предсказуемее.

6. **Заглушки для будущей функциональности.** В `handleDiagramClick` явно помечено место, куда в будущем можно добавить зум/панорамирование. Это показывает, что модуль спроектирован с прицелом на расширение.
