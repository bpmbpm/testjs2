# Как устроены `const UTILS`, `const STATE` и другие — техническое пояснение

## Короткий ответ

**Это не функции.** Это **объектные литералы** (object literals), которые содержат внутри себя функции (методы). Технически это называется **"Namespace Pattern"** (паттерн пространства имён) или **"Module Pattern"** в его простейшей форме.

---

## 1. Что это на самом деле

Возьмём для примера `UTILS`:

```javascript
const UTILS = {
    log: function(groupName, funcName, message, params = {}) {
        // ... тело функции
    },

    text: function(str) {
        // ... тело функции
    },

    getFileNameFromUrl: function(url) {
        // ... тело функции
    }
};
```

Здесь:
- `UTILS` — это **константа**, ссылающаяся на **обычный JavaScript-объект** `{}`.
- `log`, `text`, `getFileNameFromUrl` — это **свойства** объекта, значениями которых являются **функции** (их ещё называют **методами** объекта).

То есть `UTILS` сам по себе — не функция, а **контейнер** (группировка) для нескольких связанных функций.

---

## 2. Как это работает технически

### Обращение к методам
Чтобы вызвать функцию, нужно обратиться к свойству объекта через точку:

```javascript
UTILS.log('APP', 'init', 'Запуск');        // ✓ Вызов метода log
UTILS.text('  hello  ');                   // ✓ Вызов метода text
UTILS.getFileNameFromUrl('/path/file.svg');// ✓ Вызов метода getFileNameFromUrl
```

### Что происходит "под капотом"
Когда вы пишете `UTILS.log(...)`:
1. JavaScript берёт объект `UTILS`.
2. Находит у него свойство `log` (это функция).
3. Вызывает эту функцию, передавая ей контекст `this = UTILS` (это важно — см. ниже).

### Использование `this` внутри методов
Внутри методов `this` ссылается на сам объект-контейнер. Именно поэтому в `UTILS.log` можно написать:

```javascript
const name = this.getFileNameFromUrl(params.url);
//          ^^^^
//          это тот же самый UTILS
```

Это работает как "внутренний вызов другого метода того же модуля".

## 3. Как это выглядит для каждого модуля

| Константа | Тип значения | Что внутри | Как вызывается |
|-----------|--------------|------------|----------------|
| `UTILS` | Объект `{}` | 3 функции-утилиты | `UTILS.log(...)` |
| `STATE` | Объект `{}` | Объект `appState` + 4 функции | `STATE.isValid()` |
| `DATA` | Объект `{}` | 2 функции работы с данными | `DATA.loadSvg(url)` |
| `RENDER` | Объект `{}` | 3 функции отрисовки | `RENDER.renderFileList()` |
| `EVENTS` | Объект `{}` | 2 функции-обработчика | `EVENTS.handleDiagramClick()` |
| `RESIZER` | Объект `{}` | 1 функция `init` | `RESIZER.init()` |

---

## 4. Почему так сделано (плюсы подхода)

### 4.1. Группировка по ответственности
Все функции, связанные с отрисовкой, собраны в `RENDER`. Все функции, связанные с событиями, — в `EVENTS`. Это делает код **предсказуемым**: если нужно поменять логику отрисовки — смотришь только в `RENDER`.

### 4.2. Избежание глобального мусора
Без объектов у нас было бы 15+ отдельных функций в глобальной области:
```javascript
function log() {...}
function text() {...}
function loadSvg() {...}
function renderFileList() {...}
// ... и т.д.
```
Это засоряет глобальную область и повышает риск конфликта имён. С объектами в глобальной области только 6 понятных имён: `UTILS`, `STATE`, `DATA`, `RENDER`, `EVENTS`, `RESIZER`.

### 4.3. Псевдо-инкапсуляция (логическая)
Хотя технически всё публично, на уровне договорённости понятно:
- `STATE.appState` — это **данные** (не трогаем напрямую извне).
- `STATE.setSelectedFile(...)` — это **метод изменения** данных (используем его).

### 4.4. Совместимость без сборщиков
Этот паттерн работает в любом браузере **без** `import`/`export`, без Webpack/Vite, без `"use strict"`-модулей. Достаточно просто подключить `<script src="app.js">`.

## 5. Чем это НЕ является

### Это не ES6-модули
Настоящие модули выглядят так:
```javascript
// utils.js
export function log(...) {...}

// app.js
import { log } from './utils.js';
```
В нашем проекте этого нет — всё в одном файле, без `import`/`export`.

### Это не классы
Классы требуют создания экземпляра через `new`:
```javascript
class Utils {
    log(...) {...}
}
const utils = new Utils();
utils.log(...);
```
У нас же объект один, создаётся сразу, и `new` не нужен.

### Это не функции
Функция вызывается напрямую: `log(...)`. У нас же нужен "префикс": `UTILS.log(...)`.

## 6. Как это можно было бы переписать (альтернативы)

### Вариант A: Отдельные функции (без объектов)
```javascript
function log(groupName, funcName, message, params = {}) {...}
function text(str) {...}
function getFileNameFromUrl(url) {...}
```
**Минус:** 15+ функций в глобальной области, нет группировки.

### Вариант B: ES6-модули
```javascript
// utils.js
export const log = (...) => {...};
export const text = (...) => {...};

// app.js
import * as UTILS from './utils.js';
UTILS.log(...);
```
**Плюс:** Настоящая модульность.  
**Минус:** Нужен либо современный браузер с `type="module"`, либо сборщик.

### Вариант C: Классы
```javascript
class Utils {
    static log(...) {...}
    static text(...) {...}
}
Utils.log(...);
```
**Плюс:** Более "современный" синтаксис.  
**Минус:** Избыточно для простых утилит, где не нужно состояние экземпляра.

## 7. Сводная иллюстрация

```
┌─────────────────────────────────────────┐
│  const UTILS = {                        │  ← Объект (контейнер)
│                                         │
│     log: function(...) { ... },         │  ← Метод (функция внутри объекта)
│     text: function(...) { ... },        │  ← Метод
│     getFileNameFromUrl: function(...){} │  ← Метод
│                                         │
│  };                                     │
└─────────────────────────────────────────┘
          │
          │ вызов: UTILS.log('APP', 'start', 'Hi')
          ▼
   JavaScript:
   1. Берёт объект UTILS
   2. Находит свойство 'log'
   3. Вызывает функцию с this = UTILS
```

---

## 8. Итог

- `const UTILS`, `const STATE` и т.д. — это **константы-объекты**, а не функции.
- Внутри них лежат **функции-методы**, которые вызываются через точку: `UTILS.log(...)`.
- Это **классический паттерн Vanilla JS** для группировки кода по ответственности без использования сборщиков и ES6-модулей.
- Такой подход даёт: порядок в коде, отсутствие глобального мусора, логическую инкапсуляцию и полную совместимость с любым браузером.

Если захотите в будущем перейти на "настоящие" ES6-модули (`import`/`export`), структура кода почти не изменится — просто каждый объект (`UTILS`, `STATE` и т.д.) переедет в свой отдельный `.js`-файл.
