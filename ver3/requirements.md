# Требования к SVG Viewer (ver3)

## 1. Функциональные требования (Functional Requirements)
1. **FR1. Отображение списка файлов**: Система должна отображать список SVG-файлов, заданный в конфигурации, в панели `filelist`.
2. **FR2. Загрузка и парсинг SVG**: При выборе файла система должна загрузить его по URL, распарсить как XML/SVG и извлечь атрибуты основных фигур (`rect`, `circle`, `path`, `g` и др.).
3. **FR3. Отображение свойств**: Система должна отображать извлеченные атрибуты фигур в табличном виде в панели `properties`.
4. **FR4. Визуализация диаграммы**: Система должна отображать содержимое выбранного SVG-файла в панели `diagram`.
5. **FR5. Журналирование (Log)**: Система должна записывать все ключевые действия (инициализация, клики, загрузка, ошибки) в панель `log`.
6. **FR6. Изменение размера панели**: Пользователь должен иметь возможность изменять высоту панели `log`, перетаскивая её верхнюю границу.

## 2. Нефункциональные требования (Non-Functional Requirements)
1. **NFR1. Интерфейс и UX**:
   - Заголовки всех панелей (`filelist`, `properties`, `diagram`, `log`) должны оставаться видимыми (фиксированными) при прокрутке содержимого панели.
   - Записи в журнале `log` должны выводиться строго в одну строку без пустых строк-разделителей между ними.
2. **NFR2. Технологический стек**: Приложение должно быть реализовано на чистом JavaScript (Vanilla JS), HTML5 и CSS3 без использования внешних фреймворков (React, Vue, jQuery и т.д.) и сборщиков (Webpack, Vite).
3. **NFR3. Производительность**: Парсинг и отображение SVG должны происходить асинхронно, не блокируя основной поток браузера.
4. **NFR4. Совместимость**: Корректная работа в современных версиях браузеров (Chrome, Firefox, Safari, Edge).

## 3. Ограничения (Constraints)
- Список файлов жестко задается в глобальной переменной `window.svgFileList` в файле `config.js`.
- Приложение не должно модифицировать исходные SVG-файлы на сервере, работа ведется только с копией в памяти браузера.
